# 0001 — ريبو واحد بهيكل backend/ و apps/

**التاريخ:** 2026-10-18
**الحالة:** مقترح (فرع `chore/repo-restructure`)

## المشكلة

- الفريق يعمل بفروع شخصية طويلة (`abdo` و`mizo` و`anwar_branch`)، و`main` متأخر عنها بعشرات الـ commits، فكل شخص ينتظر دمج شغل غيره.
- ملفات مشتركة كبيرة يعدّل فيها الجميع: `routes/web.php` (810 أسطر) و`routes/api.php`.
- ملفات مولّدة مرفوعة على git (`node_modules` و`dist` و`bootstrap/cache` و`.env`) تسبب تعارضات لا علاقة لها بالكود.

## القرار

- ريبو واحد: `backend/` و`apps/web/` و`apps/cafe/`، و`archive/` للمتوقف.
- GitHub Flow: `main` محمي، فرع قصير لكل مهمة، PR مع مراجعة وCI.
- كل ميزة باك جديدة داخل `Modules/<Feature>/`.

## البدائل

**تقسيم إلى عدة ريبوهات** (api و web و cafe): رُفض حالياً لأن كل أعضاء الفريق يعملون على الباك والواجهة معاً، والميزات (مثل المحفظة والهدايا) تلمس الطرفين. التقسيم يجعل كل ميزة PRين في ريبوين ويضيف انتظاراً جديداً.

يُعاد النظر إذا انقسم الفريق إلى فريق باك وفريق واجهة. عندها يُستخرج أي تطبيق بتاريخه كاملاً بأمر واحد:

```bash
git filter-repo --subdirectory-filter apps/web
```
